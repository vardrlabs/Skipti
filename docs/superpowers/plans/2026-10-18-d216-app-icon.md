# D-216 The App Icon (the cut S) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cut-S icon (v9, approved 2026-10-15) on both phones in three theme versions, an App icon picker on
Appearance with "Match theme" on by default, and the cut S as Android's notification glyph in place of Lucide's bell.

**Architecture:** Assets first (the four missing Android layers and two dark iOS icons made in Affinity from the same
script that made the approved ones), then resources on each shell (iOS: three app-icon sets in the asset catalog, the
two alternates named in the build settings; Android: three adaptive icons and three `activity-alias` launcher entries
on `MainActivity`, one enabled), then one set of pure decisions per shell compared by golden tables (`AppIconChoice`,
`AppIcon`, `AppIconPlan`), then each shell's picker and switcher in parallel lanes. The icon changes at ONE moment on
both phones: when the person leaves the Appearance page, and only if it differs from the icon the phone shows.

**Tech Stack:** SwiftUI / UIKit (`UIApplication.setAlternateIconName`), Jetpack Compose and `PackageManager`
(`setComponentEnabledSetting(s)`), XCTest, JUnit. No core change, no new dependency, no cloud change, nothing deployed.

## Design

1. **Three icons, Aurora the primary.** iOS: `AppIcon` (Aurora, the primary icon, so nothing changes for anyone on
   Aurora), `AppIcon-Norse`, `AppIcon-Vardr`, each with Any, Dark and Tinted entries. Android: `ic_launcher` (Aurora,
   also the application icon shown in system Settings), `ic_launcher_norse`, `ic_launcher_vardr`, each an adaptive icon
   with background, foreground and the shared monochrome layer (Android 13+ themed icons).
2. **Android launcher entries.** `MainActivity` keeps the invite-link VIEW filter and LOSES its MAIN/LAUNCHER filter. Three
   `<activity-alias>`es, `.IconAurora` (`android:enabled="true"`), `.IconNorse` and `.IconVardr` (`"false"`), each
   `android:targetActivity=".MainActivity"`, `android:exported="true"`, `android:label="Skipti"`, its own `icon` and
   `roundIcon`, and the MAIN/LAUNCHER filter. The three alias names are PERMANENT from this unit on (a launcher stores the
   component name; renaming one drops the person's icon): add them to CLAUDE.md section 10's permanent identifiers.
   **DECIDED (controller, for the founder): all three entries are aliases, MainActivity is not one of them,** because
   `MainActivity` cannot be disabled (it is the activity every alias opens) and only enabled/disabled entries can switch.
   Cost: on the update that brings D-216, a launcher drops the old `.MainActivity` home-screen icon once (the app stays in
   the app list). SKIPTI is in internal testing, so only testers meet it; the 0.5.0 What to Test note says so.
3. **What "Match theme" means.** Stored choice `AppIconChoice`: `match` (default), `aurora`, `norse`, `vardr` (key
   `appearance.icon`, iOS UserDefaults, Android the Appearance prefs key `icon`; unknown or missing reads `match`). The
   icon wanted is `AppIconPlan.target(choice, theme)`: `match` gives the theme's icon (Aurora, Norse, Vardr Labs), any
   other choice gives itself.
4. **When the icon changes (both phones, one rule).** Only when the person LEAVES the Appearance page (iOS `.onDisappear`
   of the Appearance page; Android `DisposableEffect` `onDispose` of the Appearance route, skipped when the activity
   `isChangingConfigurations`), and only if `AppIconPlan.change(target, current)` is not nil (the phone shows another
   icon). Never at launch, never on a theme tap, never in the background on iOS. Reasons: iOS shows a system alert on
   EVERY change ("You have changed the icon for Skipti"), there is no public way to suppress it (Apple forums 811534,
   723928; the old private route stopped working in iOS 26.1), and the call needs the app active; three theme taps would
   be three alerts. Leaving the page is the end of the choosing, so the alert (iOS) or the launcher refresh (Android)
   arrives as the answer to what the person just did, at most once per visit. **DECIDED (controller, for the founder):
   the leaving moment, not each tap and not the next background.** Consequence, recorded as residue: someone who updates
   while on Norse keeps the Aurora icon until they next visit Appearance and leave; an alert at launch would be the
   surprise the founder ruled out.
   - iOS: `AppIconSwitcher.applyIfNeeded(choice:theme:)` does nothing unless `supportsAlternateIcons` and
     `applicationState == .active`; reads `alternateIconName` (nil is Aurora); calls `setAlternateIconName(target.alternateName)`
     once. A failure shows nothing and is retried at the next leave. On iOS 26.1+ the alert is drawn by SpringBoard and the
     app turns inactive behind it, so `PrivacyCover` (SkiptiApp.swift, `scenePhase != .active`) covers the page while the
     alert is up; the app lock only reacts to `.background` and does not lock. The look checks both.
   - Android: `AppIconSwitcher.applyIfNeeded(context)` reads each alias's `getComponentEnabledSetting`
     (`COMPONENT_ENABLED_STATE_DEFAULT` resolves to the manifest default: Aurora on, the other two off) into
     `AppIconPlan.current`, then writes `AppIconPlan.settings(target)`: the target ENABLED first, then the other two
     DISABLED, every one with `DONT_KILL_APP`; on API 33+ in one `setComponentEnabledSettings` call, below it in that
     order one by one (never a moment with no launcher entry). The look measures that the process survives (`pidof`
     before and after). **Contingency written in now:** if the API 34 look shows the process killed, the trigger moves to
     `MainActivity.onStop` when `!isChangingConfigurations` (the person has left the app) and the caption changes to "...
     when you leave SKIPTI"; the controller decides, records it, and says so to the founder.
5. **The picker (Appearance, S2's list vocabulary).** Placed after "Light or dark" and before "Text size" (theme, mode and
   icon are the look; text size and haptics follow). **DECIDED (controller, for the founder).** A section label "App icon"
   (`.sectionLabel()` / `SectionLabel`), then ONE `ListCard` of four rows:
   - "Match theme": S2's switch row (`ThemeSwitch`), on by default; leading tile the icon the theme gives.
   - "Aurora", "Norse", "Vardr Labs": S2's check rows, leading tile that icon's preview; the check sits on
     `AppIconPlan.target(choice, theme)` (so with Match theme on, the theme's row is checked).
   - Tapping an icon row stores that icon (Match theme turns off). Turning Match theme off stores the icon the theme
     gives (nothing visible changes); turning it on stores `match`. No disabled rows, no hidden rows.
     **DECIDED (controller, for the founder): a switch plus always-visible rows,** because the founder's words are a
     switch "on by default", and rows that stay live (a tap is a choice) avoid a dead, dimmed state.
   - Under the card, the caption (`textDim`, the detail size S1 uses for captions): "Your icon changes when you leave this
     page." Android adds a second sentence: "Some home screens remove the old icon; SKIPTI stays in your apps." **DECIDED
     (controller, for the founder): the Android sentence is a twin difference by necessity** (a launcher drops a disabled
     entry's home-screen icon; iOS replaces it in place and shows its own alert). Recorded in section 4.
   - The preview tile: the icon's own 1024 "Any" image scaled to 144 px, drawn at `iconPreview` 36 in a rounded square of
     `iconPreviewRadius` 0.225 of its side (Apple's icon corner ratio), the SAME shape in every theme (an icon keeps its
     own shape; S1's theme tiles would draw it as a Norse diamond). Decorative for accessibility; each row is spoken
     "Aurora icon", "Norse icon", "Vardr Labs icon" with the selected state; the switch "Match theme".
   - iOS: the whole section is absent when `UIApplication.shared.supportsAlternateIcons` is false.
6. **The notification glyph (Android only; iOS draws the app icon in notifications).** `res/drawable/ic_stat_skipti.xml`
   (the committed asset) replaces `ic_stat_bell.xml` in `Push.kt` and the manifest's
   `com.google.firebase.messaging.default_notification_icon`. Lucide's `bell` then draws nothing anywhere, so it leaves
   both shells' tables, both tests and NOTICE. **DECIDED (controller, for the founder): remove the dead drawing** (NOTICE
   must say exactly what ships).
7. **Sources in the tree.** `brand/skipti-icon-assets/` committed (PNGs and the glyph). `.drafts/d216/brand-src/` is
   committed as `brand/skipti-icon-src/` (geometry, SVG generator, Affinity build script; plus `svg/`'s seven editable
   masters under `brand/skipti-icon-src/svg/`), because the glyph's own header says "Generated from
   brand/s-mark-geometry.js ... Regenerate, never hand-edit" and nothing under `.drafts/` survives a clone. **DECIDED
   (controller, for the founder)**; the alternative is to leave the sources in `.drafts/` and correct the glyph's header.
   The glyph's generator was not kept (it was run in-session): Task 1 writes `brand/make_stat_glyph.py` (stdlib, a port
   of the geometry) and the committed XML is the one it writes. `brand/skipti-icon-affinity/` stays local:
